[基础语法](/pages/markdown-basic/)（CommonMark）足以应付大多数日常写作，但表格、删除线、任务列表这些高频需求它并没有规定——这就是扩展语法的用武之地。

::: warning 扩展语法不是标准
本节所有语法**都不在 CommonMark 规范内**，各家支持情况不一。它们主要来自 [GFM（GitHub Flavored Markdown）](https://github.github.com/gfm/)、markdown-it 插件与 VitePress 自带扩展。

**本站都支持**，但复制到别的平台（公众号、WPS、另一套博客）前请先在目标环境确认。投稿给本站时，请以本篇和[本站特有的 Markdown 语法](/pages/MarkdownGuide/)列出的写法为准。
:::

## 表格

用管道 `|` 分隔列，第二行用 `-` 分隔表头与表体（一个横线就够，本篇统一写三个，便于对齐）：

````md
| 语法 | 说明 |
| --- | --- |
| `*斜体*` | 行内强调 |
| `**粗体**` | 更强的强调 |
````

| 语法 | 说明 |
| --- | --- |
| `*斜体*` | 行内强调 |
| `**粗体**` | 更强的强调 |

### 对齐

在第二行的 `-` 两侧加冒号控制列对齐：`:---` 左对齐、`:---:` 居中、`---:` 右对齐。

````md
| 左对齐 | 居中 | 右对齐 |
| :--- | :---: | ---: |
| 甲 | 乙 | 丙 |
| 长一点的内容 | 内容 | 123 |
````

| 左对齐 | 居中 | 右对齐 |
| :--- | :---: | ---: |
| 甲 | 乙 | 丙 |
| 长一点的内容 | 内容 | 123 |

::: tip 写表格的几条经验
- 首尾的 `|` 可以省略，但写上更清晰、也更容易增删列；
- 表格里要显示 `|` 字符本身，得转义成 `\|`；
- 单元格内不能用多行，需要换行时用 `<br>`；
- 表格是「块级」的，前后要留空行。
:::

## 删除线

用两个波浪号包围，适合标注已过时或已更正的内容：

````md
本周六的讲座改到 ~~周三~~ 周五晚上七点。
````

本周六的讲座改到 ~~周三~~ 周五晚上七点。

本站把被划掉的文字调成淡灰，删除线本身用深一档的灰、线宽 1.5px——浏览器默认是与正文同色的 1px 细线，中文笔画密的时候几乎看不见，这样处理后「已作废」的观感比别处清楚。

## 任务列表

在列表项标记后加 `[x]`（已完成）或 `[ ]`（未完成）：

````md
- [x] 已完成的项
- [ ] 未完成的项
- [ ] 待办第三项
````

- [x] 已完成的项
- [ ] 未完成的项
- [ ] 待办第三项

::: warning 勾选框不可交互
本站的任务列表**仅作展示**，读者点击勾选不会保存——文章是静态内容，没有后端存储。需要收集填写结果请用表单类工具。
:::

## 脚注

脚注用来补充说明，正文里放一个上标编号，注释内容自动排到文末，不打断阅读节奏。

正文里写 `[^标识符]`，文档任意位置（通常放在该段之后或文末）写 `[^标识符]: 注释内容`：

````md
南开大学始建于 1919 年[^founded]，由严修、张伯苓创办。

[^founded]: 1919 年建校，初设文、理、商三科。
````

渲染后，引用处变成一个上标编号，注释正文被搬到**页面最末端**，并不留在本节里。也就是说每写一条脚注，页尾就会多出一块脚注区；为免本页凭空多出这么一块，下面用 HTML 把两处外观就地复刻（点编号会跳到样张，注释末尾的返回箭头再跳回来）：

南开大学始建于 1919 年<sup class="footnote-ref" id="footnote-demo-ref"><a href="#footnote-demo">[1]</a></sup>，由严修、张伯苓创办。

真正渲染时，页面最末端会出现这样一块：

<hr class="footnotes-sep">

<section class="footnotes">
<ol class="footnotes-list">
<li id="footnote-demo" class="footnote-item"><p>1919 年建校，初设文、理、商三科。 <a href="#footnote-demo-ref" class="footnote-backref">↩︎</a></p></li>
</ol>
</section>

标识符可以是数字或单词，**不能含空格或制表符**；它只用于把引用和注释对应起来，页面上的编号按出现顺序自动生成（所以上面这条显示为「1」）。注释里也能放多段落和代码块，只要缩进对齐即可：

````md
[^bignote]: 第一段注释。

    缩进四空格，作为注释的第二段。

    `{ my code }`
````

## 标题编号

给标题加大括号包起来的自定义 ID，可精确控制锚点。拿本文的「脚注」一节举例——它现在没手写 ID，锚点是自动生成的 `#脚注`（[点这里试试](#脚注)）；如果写成：

````md
## 脚注 {#footnote}
````

这一节的 id 就变成 `footnote`（DOM 里是 `<h2 id="footnote">脚注</h2>`）。自动 ID 平时够用，手写的价值在两点：锚点更短、更稳，以及日后改标题文字不会把已经发出去的链接打断。

本站所有标题都会**自动生成 ID**（取标题文字本身），日常用不到手写；只有标题文字过于简单、容易和别的标题撞车，或者想让锚点固定不变时才需要指定。

## Emoji

直接粘贴 emoji 字符，或输入「冒号 + 名称」的短码：

````md
去露营了！:tent: 很快回来。
````

去露营了！:tent: 很快回来。

表情很全的站点推荐 [Emojipedia](https://emojipedia.org/zh)（有中文界面）。

::: warning 短码因应用而异
短码表没有统一标准（`:tent:` 在 GitHub 与本站可用，在另一些编辑器里不认）。要保证到处都能显示，直接粘贴 emoji 字符更稳妥。
:::

## 高亮

用两个等号包围，渲染为 `<mark>文字</mark>`。注意本站渲染出来的样子和常见做法不同——不是黄色块底，而是与加粗共用的底部色带（全站统一约定，原因见本节末尾的提示）：

````md
考前请务必记住 ==允公允能，日新月异== 这八个字。
````

考前请务必记住 ==允公允能，日新月异== 这八个字。

写法细节（对齐 markdown-it-mark）：开头的 `==` 后不能紧跟空格，闭合的 `==` 前要有非空白字符，所以 `a == b` 不会被误判；等号内可以继续嵌套 `**加粗**` 与行内代码。

这是各家实现里「一半支持、一半不支持」的典型。Obsidian、Typora、Logseq 与大多数 Markdown 引擎都支持，GitHub 的 Markdown 则不支持（会原样显示 `==`）。

::: tip 本站叫「马克笔」
本站把这个语法称作**马克笔**，视觉上与加粗共用同一条底部色带（加粗＝粗体＋色带，马克笔＝色带＋自左向右的描线动画），所以它比普通高亮更显眼。本站还额外支持配色后缀 `{.tip}` / `{.caution}` / `{.warning}`（这是本站扩展），另外组合时要写成「马克笔在外」的 `==**文字**==`，顺序反过来会失效——那是 markdown-it 的定界符机制所致，不是本站规则。细节见[本站特有的 Markdown 语法](/pages/MarkdownGuide/#马克笔配色)。
:::

## 自动链接

很多处理器会把裸网址直接变成链接，本站也会：

````md
https://www.nankai.edu.cn/
````

https://www.nankai.edu.cn/

这属于 GFM 扩展，**不属于 CommonMark**，换平台可能不生效。要万无一失，请改用基础语法里的尖括号写法 `<https://…>`；反过来，不想让它变成链接时，用反引号包起来即可：`` `https://www.nankai.edu.cn/` ``。

## 代码块标题

在语言名后加 `title="文件名"`，代码块顶部会多出一条标题栏，用来标记这段代码来自哪个文件。这是 Docusaurus、MkDocs Material 等文档站的通行写法：

````md
```ts title="config.mts"
export default {}
```
````

```ts title="config.mts"
export default {}
```

VitePress 原生不认这个写法（`title=…` 会被当成无效信息丢掉），本站是自己实现的一份，标题栏整条占满代码块宽度。VitePress 自带的文件名写法是方括号 `[文件名]`，且只在代码组里生效——`::: code-group` 内并列几个代码块会渲染成可切换的 tab 标签。

## 数学公式

本站已启用 [KaTeX](https://katex.org/)。行内公式用一对 `$` 包围，独立成段的公式用两对：

````md
当 $a \ne 0$ 时，方程 $ax^2 + bx + c = 0$ 有两个实数解。

$$ x = {-b \pm \sqrt{b^2-4ac} \over 2a} $$
````

当 $a \ne 0$ 时，方程 $ax^2 + bx + c = 0$ 有两个实数解。

$$ x = {-b \pm \sqrt{b^2-4ac} \over 2a} $$

要显示美元符号本身而不触发公式，用反斜杠转义（`\$`）或放进行内代码。需要上标、下标的场合（幂运算、化学式等）也用公式表达：$X^2$、$H_2O$——Markdown 自带的上下标写法本站不渲染，不要使用。

## 思维导图

本站装的是 `@vitepress-plugin/markmap`，用 `markmap` 容器把一段 Markdown 列表画成可拖动、可缩放、可折叠的思维导图，列表层级就是节点层级：

````md
:::markmap
- Markdown
  - 基础语法
    - 标题
    - 列表
  - 扩展语法
    - 表格
    - 脚注
:::
````

:::markmap
- Markdown
  - 基础语法
    - 标题
    - 列表
  - 扩展语法
    - 表格
    - 脚注
:::

::: warning 写法与普通容器不同
`:::` 与 `markmap` 之间**不能加空格**。写成 `::: markmap` 不会渲染成导图，而是原样显示成一行 `::: markmap` 文字加一个普通列表。另外它是把列表写在「内容」位置，不像 `::: tip` 那样先写类型再写标题——因为 `markmap` 本身就是容器名。

容器内可以放 YAML frontmatter 覆盖默认值，例如 `containerHeight: 400` 调整高度、`markmap: { autoFit: true }` 让整图自适应缩放。本站全局默认高度是 500，单篇一般不用动——改小之后图会缩在上方、下方留出空白。
:::

它不属于 CommonMark、也不是本站发明的语法，是第三方插件；别的平台（GitHub、Obsidian）不会渲染这种容器，它们各自的导图语法也不相同。

## 提示容器

自定义容器由**类型**、**标题**与**内容**三部分组成：行首 `:::` 后写类型，类型后面可以跟标题，内容从下一行开始，结束时再写一行 `:::`。

本站共八种类型：`info` / `tip` / `warning` / `danger` / `details` / `note` / `caution` / `important`。默认标签已经在站点配置里统一设成中文。

### 默认标题

不写标题时显示该类型的默认标签。

**输入**

```md
::: info
这里是信息框。
:::

::: tip
这里是提示。
:::

::: warning
这里是警告。
:::

::: danger
这里是危险警告。
:::

::: details
这里是详细信息块。
:::
```

**输出**

::: info
这里是信息框。
:::

::: tip
这里是提示。
:::

::: warning
这里是警告。
:::

::: danger
这里是危险警告。
:::

::: details
这里是详细信息块。
:::

其余三种：`note` 与 `info` 同色（偏脚注式旁注）；`important` 紫色；`caution` 与 `danger` 同为玫红，只靠标签区分，同一段内容挑一个即可。

### 自定义标题

在类型后面直接跟标题文字即可。标题必须与 `:::` 同一行，写到下一行会被当成正文。

**输入**

````md
::: danger STOP
危险区域，请勿继续
:::

::: details 点我查看代码
```js
console.log('Hello, NKUwiki!')
```
:::
````

**输出**

::: danger STOP
危险区域，请勿继续
:::

::: details 点我查看代码
```js
console.log('Hello, NKUwiki!')
```
:::

GitHub 不认 `:::` 这套写法（会原样显示成文字），要两边都能渲染请用下一节的告警。嵌套容器时外层围栏要加长到 `::::`（内层仍写三个）——两层都用三个冒号时，内层能嵌进去，但外层会提前收尾，多漏出一行字面 `:::`。

## GitHub 风格的警报

GitHub 的告警是一个引用块：首行写类型标记，正文按普通引用写。本站同样识别，渲染成与上面相同的容器样式：

````md
> [!NOTE]
> 强调用户在快速浏览文档时也不应忽略的重要信息。

> [!TIP]
> 有助于用户更顺利达成目标的建议性信息。

> [!IMPORTANT]
> 对用户达成目标至关重要的信息。

> [!WARNING]
> 因为可能存在风险，所以需要用户立即关注的关键内容。

> [!CAUTION]
> 行为可能带来的负面影响。
````

> [!NOTE]
> 强调用户在快速浏览文档时也不应忽略的重要信息。

> [!TIP]
> 有助于用户更顺利达成目标的建议性信息。

> [!IMPORTANT]
> 对用户达成目标至关重要的信息。

> [!WARNING]
> 因为可能存在风险，所以需要用户立即关注的关键内容。

> [!CAUTION]
> 行为可能带来的负面影响。

GitHub 只有这五种，标签由类型固定、不能自定义；要自己起标题就用 `:::` 容器。

## 兼容性速览

| 语法 | 出处 | GitHub | 本站 | 备注 |
| --- | :---: | :---: | :---: | --- |
| 表格 | GFM | ✅ | ✅ | 最通用的扩展 |
| 删除线 | GFM | ✅ | ✅ | `~~文字~~` |
| 任务列表 | GFM | ✅ | ✅ | 仅展示，不可交互 |
| 自动链接 | GFM | ✅ | ✅ | 裸网址变链接 |
| 脚注 | GFM 扩展 | ✅ | ✅ | 自动排到文末 |
| Emoji 短码 | GitHub | ✅ | ✅ | 短码表不统一 |
| 标题编号 | markdown-it | ❌ | ✅ | `{#id}` |
| 高亮 | markdown-it | ❌ | ✅ | `==文字==` |
| 代码块标题 | Docusaurus / MkDocs | ❌ | ✅ | `title="文件名"`，VitePress 原生不认，本站自己实现 |
| 数学公式 | KaTeX | ✅ | ✅ | `$…$` |
| 提示容器 | VitePress | ❌ | ✅ | `::: tip`，GitHub 会原样显示 |
| GitHub 告警 | GitHub | ✅ | ✅ | `> [!NOTE]`，两边通用 |
| 思维导图 | markmap 插件 | ❌ | ✅ | `:::markmap`，把列表画成脑图 |

「出处」列写的是该语法**最流行的来源**，不等于只有它支持。判断某平台支不支持，最快的办法是贴进去预览一眼。
