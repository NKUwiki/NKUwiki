## 卡片列表（cardlist）

`lib/content/cardlist.ts` 是一个 markdown-it 插件：把 `::: cardlist` 容器包裹的 Markdown 表格重渲染成卡片网格，数据仍然写在表格里，方便编辑：

```md
::: cardlist
|   名称    |        加入方式         |                                   二维码                                    |
| :-------: | :---------------------: | :-------------------------------------------------------------------------: |
| NKUwiki组 | :qq:[1108024910](链接)  | <QrCode src="https://qm.qq.com/q/xxxx" label="NKUwiki项目组" :size="128" /> |
|  某社团   | :wechat: 公众号私信加群 |                                                                             |
:::
```

### 表头（列名）决定渲染方式

| 列名                | 行为                                                                                   |
| ------------------- | -------------------------------------------------------------------------------------- |
| 第一列              | 卡片标题                                                                               |
| `头像`              | 卡片头像，写 `![](/img/…/xx.jpg)`、链接或裸路径均可                                    |
| `加入方式` / `群号` | 渲染为联系区，支持[图标短码](#图标短码)与链接；群组模式还会自动从单元格提取 QQ 号      |
| `二维码`            | 写 `<QrCode>` 组件，见下文                                                             |
| `备注`              | 渲染为卡片上的徽章                                                                     |
| `文章` / `详情`     | 填一个链接（如 `[查看详情](/pages/Xxx/)`），整张卡片可点击跳转；该列本身不显示在卡片上 |
| `菜品`              | 美食卡评分，写四段数字如 `4-3-4-4`，自动标注菜品/菜量/环境/总体                        |
| `评价` / `主要工作` | 渲染为描述段落                                                                         |
| 其他列名            | 渲染为通用的「列名： 内容」字段，空单元格自动跳过                                      |

表头里出现「群号 / 加入方式 / 二维码」时整表按**群组卡片**渲染（带头像与联系区），否则按**美食卡片**渲染（带菜品评分），无需手动指定。

### 单元格内的配套组件

以下三个组件都设计在 cardlist 单元格里使用，各写一行即可：

| 组件        | 写法                                                                     | 参数                                                                                                                                   |
| ----------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| QrCode      | `<QrCode src="https://qm.qq.com/q/xxxx" label="群名称" :size="128" />`   | `src` 必填；`label` 悬停大图标题；`size` 卡片图标尺寸（px），默认 `128`                                                                |
| HoverMedia  | `<HoverMedia kind="image" src="/img/03/03/xx.png" label="负责人微信" />` | `src` 必填；`kind` 为 `qr`（默认，显示「扫码」）或 `image`；`label` 悬停提示，`qr` 默认「扫码加入」；`size` 预览尺寸（px），默认 `200` |
| CopyContact | `<CopyContact value="123456789" />`                                      | `value` 必填，点击复制到剪贴板并提示「已复制」                                                                                         |

### 图标短码

单元格中写 `:名称:` 会替换为对应图标，当前支持 `:qq:`、`:wechat:`、`:feishu:`、`:mail:`、`:link:`；需要更多图标时在 `lib/content/cardlist.ts` 的 `cardIcons` 中追加（需 import 对应的 `@iconify-icons/ri/*` 图标）。

### 群头像生成（GroupAvatar）

「头像」列缺省时，cardlist 会为每个卡片自动生成 `<GroupAvatar>`：候选头像按「手动 `avatar` 字段 → 按 QQ 号请求 `p.qlogo.cn` 群头像」排列，加载失败自动顺延，全部失败显示站点图标。组件本身一般不手写。

## 应用卡片（AppCards）

「图标 + 名称 + 一句话简介」的紧凑卡片网格，数据写在 `links` 属性里：

```md
<AppCards :links="[
	{ text: '菜鸟', desc: '查快递物流与取件码', link: '/pages/Delivery' },
	{ text: '学习通', desc: '签到、网课、作业与考试' }
]" />
```

| 字段   | 说明                                                                                                                   |
| ------ | ---------------------------------------------------------------------------------------------------------------------- |
| `text` | 应用名称，最多两行，超出省略                                                                                           |
| `icon` | 图标图片，写站内路径（如 `/img/04/xx.png`，图片放 `docs/public/` 下，自动拼 base）或外链均可；缺省时显示名称首字的方块 |
| `desc` | 一句话简介，默认不限行数                                                                                               |
| `link` | 整卡跳转链接：站内路径当前页跳转，http(s) 外链新窗口打开，其余协议一律忽略                                             |

可选 props：`width`（列宽下限，默认 `12em`）、`textLines`（名称行数上限，默认 `2`）、`descLines`（简介行数上限，默认不限制）。

注意 `links` 是 Vue 属性值，`[文字](链接)` 这类 Markdown 语法不会被渲染，跳转请使用 `link` 字段。

## 图片画廊（Gallery）

`<Gallery>` 容器包裹若干 Markdown 图片，按各图的原始宽高比排成等高行、逐行铺满正文宽度：

```md
<Gallery :row-height="220" :gap="8">

![振声楼](/img/04/08/振声楼.png)
![新开湖](/img/04/08/新开湖.png)
![马蹄湖](/img/04/08/马蹄湖.png)

</Gallery>
```

| 属性         | 默认值 | 说明                                                   |
| ------------ | ------ | ------------------------------------------------------ |
| `row-height` | `220`  | 每行的目标高度（px），行内图片按原始比例缩放到统一行高 |
| `gap`        | `8`    | 图片间距（px），行内与行间共用                         |

实现要点：

- 起始标签、图片与结束标签之间**各保留一个空行**，否则容器内不被当作 Markdown 解析，图片不显示
- 图片在全部加载完成前按原始尺寸平铺（同时是无 JS 时的降级形态），加载完成后由 `ResizeObserver` 触发重排
- 布局算法是纯函数 `lib/content/gallery.ts`（贪心分行、行内等高铺满、末行不拉伸），单测在 `tests/gallery.test.ts`

## 友情链接（FriendLinks）

`lib/content/flink.ts` 是一个 markdown-it 插件：把 md 里的 `<flink>` 数据块解析成 props 注入 `FriendLinks` 组件（数据与样式分离，友链数据直接在 md 中编辑）。每行一个字段，空行分隔条目：

```md
<flink>

- name: 站点名称
  image: /img/10/10/头像.png
  url: https://example.com/
  description: 一句话介绍
  tag: 兄弟院校
  qr: true

</flink>
```

`name` 与 `url` 必填，`image`（头像）、`description`、`tag`（徽章）、`qr`（微信公众号，卡片不可点、悬停显二维码）、`preview`（悬停查看图片）可选；`url` 只接受站内相对路径与 http(s) 外链，其余协议的条目静默丢弃。完整用例见[友情链接](/pages/FriendshipLinks/)页。

## 分享图下载（DownloadPageImage）

空组件，渲染一组分享按钮：点击后用 `share-image.ts`（modern-screenshot）把当前页面截图拼上站点二维码生成分享长图并下载。直接写：

```md
<div class="section" style="text-align:center;">
  <DownloadPageImage />
</div>
```

## 全站搜索（WikiSearch）

导航栏放大镜或 `Ctrl + K`（macOS `Cmd + K`）呼出。接线方式：

- 索引由 `lib/search/search.ts` 在构建期扫描全部文章生成，经 data loader `search.data.ts` 懒加载（不进首屏主包）；
- 分词与摘要高亮是双端共用的纯函数 `lib/search/searchCore.ts`——MiniSearch 默认分词不识别中文，自建分词按词命中并标注章节。

## 阅读增强（Nolebase）

导航栏右侧的「阅读增强」菜单由 `@nolebase/vitepress-plugin-enhanced-readabilities` 提供，WikiLayout 挂载两个入口：桌面端 `NolebaseEnhancedReadabilitiesMenu`（`#nav-bar-content-after`）与移动端 `NolebaseEnhancedReadabilitiesScreenMenu`（`#nav-screen-content-after`）。提供两类能力：

- **布局切换**：调整页面宽度，四种模式——默认（Original）、全屏宽度（FullWidth）、仅侧边栏宽度可调、两者宽度均可调，后两种附带内容/页面最大宽度的滑杆；适合大表格与卡片页临时放宽正文
- **聚光灯**：以光标为中心高亮当前阅读区域，有「下方遮罩（Under）」与「侧边竖线（Aside）」两种样式，Aside 的竖线在 `theme/styles/nolebase.css` 里调成品牌色

站点侧的定制：桌面端聚光灯默认开启——主题入口只在 localStorage 无记录时写入默认值，用户改动后完全尊重其选择；触屏设备插件自身禁用聚光灯。设置均持久化在 localStorage，插件主题适配样式集中在 `theme/styles/nolebase.css`。

## 文章元信息与作者（ArticleMeta / ArticleAuthors）

`ArticleMeta` 在构建期由 `config.mts` 的 `article-title` core rule 注入正文最前（防重复插入有 `wikiTitleInserted` 标记），渲染分类面包屑、标题、日期、字数与阅读时间、标签；页尾「本文作者」由 WikiLayout 挂载 `ArticleAuthors` 渲染，作者来自 frontmatter 的 `author` 字段，经 `lib/data/authors.ts` 的 `collectAuthors` 与站点侧成员表（`docs/.vitepress/data/members.ts`）补全头像与联系方式。字段写法见[贡献指南](/pages/Contributing/#author-的写法)。

## 页面历史（GitHistory）

WikiLayout 挂载 `GitHistory`（frontmatter `hideChangelog: true` 可单篇隐藏）。数据链路：`docs/.vitepress/scripts/gen-history.mjs` 用 `git log --follow` 生成 `history.json`（dev/build 前自动执行、带缓存）→ `transformPageData` 按页注入各自的提交记录（全量数据不进主题入口包）→ `contributors-mapping.json` 把邮箱/姓名映射到 GitHub 用户名。

## 公告横条（AnnouncementBar）

固定在视口顶部的全站公告，配置在站点侧 `docs/.vitepress/data/announcement.ts`：

```ts
export const announcement = {
	message: '',    // 公告文字；空字符串表示隐藏（默认）
	background: '', // 可选，留空用主题色底
	color: '',      // 可选，留空白色文字
}
```

接线方式：`config.mts` 经 `vite.define` 以 `__ANNOUNCEMENT__` 双重序列化注入（对象配置需 `JSON.stringify(JSON.stringify(...))`，包内 `lib/data/announcement.ts` 解析，未注入返回 null）；横条通过 VitePress 内置的 `--vp-layout-top-height` 约定让下方区域让位——CSS 给 40px 兜底值，组件挂载后用 ResizeObserver 实测高度覆盖，适配文字换行。修改后需重新构建（`pnpm dev` 需重启）。

## 校园地图（MapView）

[校园地图](/map)由 `MapView.vue` 渲染（上游地图项目整体移植，不参与 ESLint），基于高德 JS API，覆盖八里台、津南两校区 17 类点位，支持分类筛选、详情卡、关联文章跳转与导航。组件不内置数据：点位、分类、校区与高德密钥都在站点侧 `docs/.vitepress/data/map-data.js`，经 `data` prop 注入（格式示例见包内 `map-data.example.js`）。

### 新增或修改点位（BUILDINGS）

地图上的每个标点对应 `BUILDINGS` 数组里的一条数据：

```js
{
  "id": "n_landmark_01",                  // 唯一标识，不要与其他点位重复
  "name": "南开大学主楼",                  // 标点与列表里显示的名称
  "category": "landmark",                 // 分类 key，必须是 CATEGORY_CONFIG 里已有的
  "campusId": "n",                        // 所属校区："n" 八里台 / "j" 津南
  "coord": [117.171274, 39.102101],       // 坐标 [经度, 纬度]
  "desc": "八里台校区标志性主楼……",        // 详情卡上的介绍文字
  "photos": ["/map/pic/xxx.png"],         // 详情卡图片，可选，文件放 docs/public/map/pic/
  "article": "/pages/BalitaiCampus/#主楼"  // 关联文章，可选，见「点位关联文章」
}
```

| 字段       | 说明                                                                                                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`       | 唯一标识。惯例是「校区前缀 + 分类 + 序号」，如 `n_canteen_02`、`j_library_01`                                                                                              |
| `name`     | 标点气泡、左侧列表与详情卡显示的名称                                                                                                                                       |
| `category` | 决定标点图标与颜色，可用取值见[可用的 category](#可用的-category)                                                                                                          |
| `campusId` | `"n"` 八里台校区、`"j"` 津南校区                                                                                                                                           |
| `coord`    | `[经度, 纬度]`。用[高德坐标拾取器](https://lbs.amap.com/tools/picker)搜索或点选获取（GCJ02 坐标，不要用 GPS 原始坐标或百度坐标，会有偏移）。导航外链与步行路线都会自动换算 |
| `desc`     | 点击标点后详情卡里的介绍，一两句话即可                                                                                                                                     |
| `photos`   | 详情卡图片数组，可选。图片放进 `docs/public/map/pic/`，路径以 `/map/pic/` 开头                                                                                             |
| `article`  | 关联文章，可选，用法见[点位关联文章](#点位关联文章)                                                                                                                        |

#### 可用的 category

点位的 `category` 必须是 `CATEGORY_CONFIG` 里已有的 key，当前共 17 个：

| key          | 显示名   | 典型用途                               |
| ------------ | -------- | -------------------------------------- |
| `landmark`   | 地标建筑 | 主楼、马蹄湖、纪念雕塑等标志性地点     |
| `teaching`   | 教学楼   | 公共教学楼、电教中心                   |
| `college`    | 学院楼   | 各学院的教学科研楼（伯苓楼、省身楼等） |
| `admin`      | 行政楼   | 机关办公楼、出版社                     |
| `library`    | 图书馆   | 各校区图书馆                           |
| `dormitory`  | 学生宿舍 | 学生公寓区                             |
| `canteen`    | 食堂     | 各食堂                                 |
| `sports`     | 运动场馆 | 田径场、体育馆、游泳馆                 |
| `theater`    | 剧场     | 音乐厅、演出与活动场地                 |
| `hospital`   | 校医院   | 校区医院                               |
| `gate`       | 校门     | 各校门                                 |
| `busstation` | 校车站   | 校内巴士站点                           |
| `transit`    | 轨道交通 | 地铁站                                 |
| `express`    | 快递点   | 快递驿站                               |
| `shop`       | 商铺     | 校内超市、门市                         |
| `food`       | 附近美食 | 校外餐馆（如西南村）                   |
| `tool`       | 维修点   | 打印、维修等服务点                     |

都不合适时，需要在 `map-data.js` 里新增分类——文件头注释写明了要同步修改的三处配置；不熟悉的话也可以请管理员代为添加。

### 点位关联文章

详情卡可以带一个**「查看相关文章」**按钮，点击跳转到站内对应文章；链接带锚点时会**直接定位到文章里的那一章**。在点位数据里加 `article` 字段即可：

```js
"article": "/pages/BalitaiCampus/#主楼"
```

- 链接写文章的 `permalink`；`#` 后面填文章里的某个 `##` 章节标题（与标题文字一致），不写 `#` 则打开文章开头
- 没写 `article` 字段的点位不显示按钮
- 写「校园建筑」类文章时，建议章节标题与地图点位名称对应，方便这样关联

## 首页与专题页（WikiHome / ArticleIndex）

首页（WikiHome）、分类/标签/归档专题页（ArticleIndex）与「关于我们」的成员墙（MemberGrid）由站点侧组件渲染，直接消费 data loader（`catalog.data.ts` 等）——数据来自 `lib/content/catalog.ts` 与 `category.ts` 对 `docs/` 编号目录的构建期扫描，侧栏、分类、标签、归档与搜索索引全自动生成，无需手工维护。首页「活动」栏读取 `docs/activity/`（不生成独立文章页，字段说明见[其目录说明](https://github.com/NKUwiki/NKUwiki/blob/main/docs/activity/README.md)）。

## 一键构建脚本（build.ps1）

仓库根目录的 `build.ps1`（PowerShell 5.1+）把本地的「构建 → 预览」收成一条命令：

```powershell
./build.ps1              # 自动在 5000-60000 范围内挑选空闲端口
./build.ps1 -Port 5173   # 指定端口，跳过随机挑选
```

流程：

| 步骤     | 说明                                                                                   |
| -------- | -------------------------------------------------------------------------------------- |
| 安装依赖 | 仓库里没有 `node_modules` 时执行 `pnpm install --frozen-lockfile`                      |
| 构建站点 | `pnpm build`，含页面更新时间生成与 Markdown 死链校验                                   |
| 挑选端口 | 随机选一个空闲端口（默认在 5000–60000 范围内），避免和其他程序冲突导致预览起不来       |
| 启动预览 | 用 `vitepress preview` 把刚构建的产物跑在本地服务器上，浏览器打开即可查看，Ctrl+C 退出 |
