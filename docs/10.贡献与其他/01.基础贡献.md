### 文章结构

文章由两部分组成

1. Frontmatter
2. 正文

### Frontmatter

Frontmatter是文章的一些基本信息，必须在Markdown文件的**顶部**，并且被包裹在一对三短划线中间。示例：

```
---
title: 基础贡献
description: 向NKUwiki投稿的基础指南：Markdown写作规范、文章Frontmatter字段、标题图片表格等语法，以及内容提交方式。
date: 2026-09-10
lastUpdated: 2026-09-14
author:
  - name: Cure
categories:
  - 贡献
    - 测试
tags:
  - 基础贡献
  - 测试
permalink: /pages/BasicContribution/
---
```

此Wiki常用Frontmatter内容即为以上内容

- **title** 会在正文开头生成一个**1级标题**，会**覆盖**掉手动写的一级标题，所以你可以不单独写1级标题
- **description** 该文章的简介
- **date** 为文章创建日期，格式为 YYYY-MM-DD，后续修改时保留。
- **lastUpdated** 为最近一次内容更新日期，格式为 YYYY-MM-DD。新增、删除或修正正文信息、文字勘误、措辞修改，以及补充或修复有效资料链接时，在同一个提交中手动更新此字段；修改文章引用的脑图或组件中的实际内容时也需同步更新。纯排版、分类、SEO 元数据、文件迁移和等价的组件替换不更新日期。
- 新文章只填 date；有后续内容更新时再添加 lastUpdated。未填写时不显示页尾更新时间，也不进入“最近更新”列表。构建时不会从 Git 自动生成日期，普通目录和归档仍可按创建日期展示文章。
- **author** 文章作者，可不写：不写时页尾只列 Git 提交历史里的作者，索引卡片显示默认的`NKUwiki-Group`。写法见下节「作者与头像」。
- **categories** 即为文章分类，可以多次缩进表示嵌套（子目录）
- **tags** 即为标签
- 短横线“-”，使用tab缩进。
- 一般情况下categories和`.md`文件所在目录相对应，具体可参考同目录文件的写法。
- **permalink** 可以不写，会自动生成链接。但是建议写，以固定文章链接

更多内容请查看<https://vitepress.dev/zh/guide/frontmatter>

### 作者与头像

#### 作者从哪里来

文章页尾的「本文作者」会合并两个来源，去重后全部列出（可能有十位以上）：

1. frontmatter 的 `author` 字段；
2. 该文件的 Git 提交历史，构建时自动读取，无需手写。

#### author 的写法

**只支持一种写法**：数组，元素是 `{ name, email, avatar }` 对象；只有一个作者时也这样写。

```
author:
  - name: Cure
    email: mailto:1352862815@qq.com
  - name: NKUwiki
    avatar: https://github.com/NKUwiki.png?size=80
```

每个元素的字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| name | 是 | 显示的名字；缺了这一条会被忽略 |
| email | 否 | 写 `a@b.com` 或 `mailto:a@b.com` 都行，用于和 Git 记录合并、取头像 |
| avatar | 否 | 头像图片地址，例如 `https://github.com/用户名.png?size=80` |

#### 写法约束

- 必须是数组：`author: Cure`、`author: { name: Cure }`、数组里直接写名字字符串，这些写法都不再支持，会被忽略。
- 键名是 `author`（单数）。页面数据里的 `authors` 是构建时生成的内部字段，写在 md 里无效。
- 名字本身带空格没问题，会整体当作一个名字；多个作者就写多个数组元素。
- 如下写法会被忽略：`author:` 空值、字符串、数字、嵌套数组，以及没有 `name` 的元素。
- 名字或邮箱里有 `: `、`#`，或开头是 `@`、`?`、`&`、`*` 这类 YAML 特殊字符时，用引号包起来，例如 `email: "mailto:a@b.com"`。

#### 合并、头像与兜底

- 去重规则：邮箱、GitHub 用户名或姓名任意一项相同即算同一个人。想让它和 Git 提交记录合并成一条，就填上提交时用的邮箱（或写成一致的姓名）。
- 页尾顺序：frontmatter 里写的作者排在前，其余按提交次数从多到少，鼠标悬停可看到提交次数。
- 头像推导顺序：`avatar` → GitHub 邮箱 → GitHub 头像，其他邮箱 → Gravatar，都没有 → 姓名首字生成的本地头像；远程头像加载失败也会回退到首字头像。
- 两个来源都没有作者时（比如文件还没提交、仓库历史被压缩），页尾显示 `NKUwiki-Group`，链接 <https://github.com/NKUwiki/NKUwiki>，头像用 GitHub 头像。
- 索引和归档卡片显示 frontmatter 里的名字（多个作者用「、」连接）；完全没写 `author` 时卡片才回退显示 `NKUwiki-Group`。

### 基础语法

Markdown可以看做是有点文字样式和排版的TXT文本文件，因此学习很快，门槛极低。

这里将会介绍基础的Markdown语法，学会后即可撰写简单的文章。

需要注意的是，我们在写文本的时候大多写的是中文，然而中文下的标点为全角标点，如`，。？！（）【】：；“”`等，这些标点不被Markdown语法所认可，也无法转义。

此Wiki常用Markdown语法有：

### 1. 标题 [数个 "#" + 空格 前置]

```
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
```

设置标题后，标题会在右侧的`本页目录`中分级显示，且可以跳转。

### 2. 段落

Markdown一段文字就是一个段落，要创建新段落，请至少回车两次，保证两段文字之间至少有**一个空行**。也可以使用HTML语法`</br>`换行（非必要不建议）。

### 3. 加粗 [用 "**" 包围]

```
**南开大学欢迎你**
```

**南开大学欢迎你**

可以对选中的文本按下`Ctrl` + `B`实现该效果。

### 4. 斜体 [用 "*" 包围]

```
*欢迎大佬补充* 
```

*欢迎大佬补充* 

（PS: ***斜体并强调*** [用 "***" 包围]）

可以对选中的文本按下`Ctrl` + `I`实现该效果。

### 5. 列表

列表有**有序**和**无序**之分。

有序列表使用[数字 + "." + 空格 前置]。数字可以不连续，**Markdown会自动修正数字顺序**。嵌套使用TAB键，或者加三个空格。
1. 列表1
2. 列表2
   1. 列表3
      1. 列表4
   2. 列表5 
3. 列表6
```
1. 列表1
2. 列表2
   1. 列表3
      1. 列表4
   2. 列表5 
3. 列表6
```

无序列表使用["-" + 空格 前置]。一个短横线表示一个点。嵌套列表请在开头加两个空格
- 无序列表1
- 无序列表2
  - 无序列表2.1
- - 无序列表2.2
    - 无序列表3
```
- 无序列表1
- 无序列表2
  - 无序列表2.1
- - 无序列表2.2
    - 无序列表3
```

有序和无序可嵌套，一般用TAB或者打出和上一级标题相同长度的空格。有序标题是3个空格，无序标题是2个空格。

1. 主要任务
   - 子任务A
   - 子任务B
     1. 详细步骤1
     2. 详细步骤2
   - 子任务C
2. 次要任务
```
1. 主要任务
   - 子任务A
   - 子任务B
     1. 详细步骤1
     2. 详细步骤2
   - 子任务C
2. 次要任务
```

### 6. 链接

可用于访问内、外部资源、网页。如[百度](https://www.baidu.com "百度一下你就知道")，[入学准备](/pages/Preparation)

WIki内部资料引用为相对路径，即Frontmatter的 permalink ，或者是网址`https://freshnkuer.wiki/pages/BasicContribution/`中`https://freshnkuer.wiki`后面的部分，如`/pages/BasicContribution/`

```
[链接名称](链接地址)
[链接文字](链接地址 "可选的标题")
<链接地址>

[百度](www.baidu.com "百度一下你就知道")
[入学准备](/pages/Preparation)
```

### 7. 插入图片

Markdown 图片语法格式如下：
```
![替代文字](图片路径)
![替代文字](图片路径 "图片标题")
```
由于Markdown不支持图片大小设置，所以有时候会使用HTML的`<img>`标签。

本网站所有图片相对路径为`\img\`，也可以引用外部网络图片。

### 8. 表格

一个最简单的表格由**表头行**、**分隔行**和**数据行**组成，列与列之间用**英文竖线`|`**分隔，行首和行尾也各写一个`|`方便对齐。

| A列            | B列      | C列                           |
| -------------- | -------- | ----------------------------- |
| `# 标题`       | 一级标题 | 标题                          |
| `**文字**`     | 加粗     | **文字**                      |
| `*文字*`       | 斜体     | *文字*                        |
| `[文字](链接)` | 插入链接 | [百度](https://www.baidu.com) |

```
| 语法           | 作用     | 效果                          |
| -------------- | -------- | ----------------------------- |
| `# 标题`       | 一级标题 | 标题                          |
| `**文字**`     | 加粗     | **文字**                      |
| `*文字*`       | 斜体     | *文字*                        |
| `[文字](链接)` | 插入链接 | [百度](https://www.baidu.com) |
```

第二行的分隔行使用短横线`-`，对数量没有要求，还可以配合冒号`:`控制每一列的对齐方式：

- `:---` 左对齐（默认）
- `:---:` 居中对齐
- `---:` 右对齐

| 左对齐 | 居中  | 右对齐 |
| :----- | :---: | -----: |
| 1      |   2   |      3 |

```
| 左对齐 | 居中  | 右对齐 |
| :----- | :---: | -----: |
| 1      |   2   |      3 |
```

单元格内同样可以使用加粗、斜体、链接等行内语法；如果需要在单元格内换行，可以使用 HTML 标签 `</br>`。

注意事项：
- 竖线、短横线、冒号都要使用**英文**符号，行首和行尾的竖线可以省略，但建议写上。
- 每一行的单元格数量最好保持一致，否则表格可能显示错乱。
- 表格前后请留一个空行，否则可能无法被正确识别为表格。

### 9. 卡片组件与图标短码

本站「群汇总」等页面使用 `::: cardlist` 自定义容器：把其中的普通 Markdown 表格渲染为卡片。在卡片表格的单元格内，可以用**图标短码**手动插入对应品牌的图标，无需手写 HTML，且图标会与文字显示在同一行。

在单元格中写入 `:名称:` 即可被替换为对应的 SVG 图标：

| 短码 | 对应图标 | 常见用途 |
| --- | --- | --- |
| `:qq:` | QQ 图标 | QQ 群号、QQ 联系方式 |
| `:wechat:` | 微信图标 | 微信号、微信群 |
| `:feishu:` | 飞书图标（官方 logo，单色品牌蓝） | 飞书群、飞书文档/链接 |
| `:mail:` | 邮箱图标 | 邮箱地址 |
| `:link:` | 外链图标 | 普通网页链接 |

注意事项：

- 短码名称必须以**小写字母**开头（如 `:qq:`、`:feishu:`），后面可跟字母、数字或连字符。
- 多个短码可连续书写，例如 `:qq::feishu:` 会依次渲染两个图标。
- 名称若不在内置注册表中，文本会**原样保留**（不报错），例如 `:abc:` 仍显示为 `:abc:`。
- 普通冒号文本（如时间 `12:00`、比例 `1:2`）**不受影响**——因为短码正则要求名称以字母开头，不会误伤数字。
- 图标统一取站点品牌色，与整套图标风格一致；飞书图标为官方 logo 单色化，不再是之前的占位图标。
- 图标短码仅在 `::: cardlist` 卡片块内的单元格生效，普通 Markdown 表格中不会被替换。
