本篇介绍**写作层面的规范**：文章放在哪里、怎么命名、Frontmatter 怎么写、图片放哪里、能用哪些站点功能。至于通过什么渠道把文章交给我们，见姊妹篇[贡献方式](/pages/ContributionMethods/)。

## 文章放在哪里

正文都放在 `docs/` 下**带编号**的目录里，编号决定侧栏顺序。按内容类型对号入座：

| 内容类型 | 放到 |
| --- | --- |
| 入学手续、报到、军训、交通、反诈防骗 | `docs/01.新生入学/` |
| 学分绩点、选课、考试、推免保研、竞赛证书 | `docs/02.浅谈学习/` |
| 兴趣群、老乡群、学生组织、实验室汇总 | `docs/03.群汇总/` |
| 单个社团/组织的详细介绍页 | `docs/03.群汇总/05.组织详情/` |
| 快递外卖、美食、周边、APP、校园建筑等日常 | `docs/04.校园生活/` |
| Markdown、Git、编程、AI 等工具类内容 | `docs/05.计算机知识/` |
| 本站协作说明、关于我们、友情链接 | `docs/10.贡献与其他/` |
| 首页「活动」栏的活动信息 | `docs/activity/`（不生成独立页面） |

几个约定：

- **不要新建顶层编号目录**。想加新大类，先在群里或 Issue 里提一句，多数内容能并入现有分类。
- 目录下可以再建**子目录**形成子分类（如 `04.校园生活/08.校园建筑/`），子目录里的文章在侧栏与分类页都会多一层。
- `categories/`、`tags/`、`archives/` 这些无编号目录是站点功能页，**不要往里面写文章**。
- 内容横跨多类时，放进主要服务的那一类，再用 `categories` / `tags` 补充。

## 命名规则

- 文件与目录都以「**编号.名称**」命名，如 `01.快递和外卖.md`；展示时自动去掉数字前缀，编号只决定排序。
- 编号惯例：`00.` 放概览，`01.`–`09.` 放主题文章，`10.` 之后放 Q&A、附录等收尾内容，不必强行连续。
- 文件名会参与链接的自动生成，建议在 [Frontmatter](#frontmatter) 里手写 `permalink` 固定链接。
- 一篇文章一个 `.md` 文件；文件名里避免 `? # &` 等符号。

## Frontmatter

Frontmatter 是文件顶部的元信息，被一对三短划线包裹。完整示例：

```yaml
---
title: 快递和外卖
description: 校内快递点与外卖取送指南。
date: 2026-09-01
lastUpdated: 2026-09-09
categories:
  - 校园生活
tags:
  - 校园生活
permalink: /pages/Delivery
order: 2
---
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 文章标题，会覆盖正文里手写的一级标题，所以正文**不要再写一级标题** |
| `description` | 建议 | 一句话简介，用于分享卡片与页面描述 |
| `date` | 是 | 创建日期 `YYYY-MM-DD`，后续修改保留 |
| `lastUpdated` | 条件 | 最近一次内容更新日期。新增、删改正文或修订信息时与内容同一提交更新；纯排版、分类调整不更新。未填写则不显示页尾更新时间 |
| `categories` | 可选 | 补充分类。目录层级本身就是分类（如 `04.校园生活/08.校园建筑/` 自动是「校园生活/校园建筑」），一般不用再写 |
| `tags` | 可选 | 标签，出现在标签页与文章标题旁 |
| `permalink` | 建议 | 固定访问链接，不写则由文件路径自动生成（带编号、会随改名变化），强烈建议手写 |
| `order` | 可选 | 控制侧栏与专题页排序，数字越小越靠前；没写的排在写了的后面并保持原顺序 |
| `author` | 可选 | 页尾「本文作者」。不写则显示兜底的 `NKUwiki-Group` |

### author 的写法

支持两种写法，可以在同一个数组里混用：

```yaml
# 写法一：只写名字字符串，其余信息（GitHub、头像、联系方式）按名字到
# docs/.vitepress/lib/data/members.ts 的成员表里查
author: [Cure, NKUwiki-Group]

# 写法二：对象形式，适合不在成员表里的客串作者就地补字段；
# 显式写了的字段会覆盖成员表里的同名信息
author:
  - name: 客串作者        # 必填，缺 name 的整条忽略
    github: someones      # GitHub 用户名：自动取头像与个人页链接
    avatar: https://img.example.com/avatar.png   # 自定义头像，优先级最高
    link: https://blog.example.com               # 点击头像跳转的链接
    contact: QQ：123456789                       # 悬停头像时显示的联系方式
    email: guest@example.com                     # 邮箱（写裸邮箱会自动补 mailto:）
```

各信息的取值优先级（从前到后）：

- **头像**：frontmatter 的 `avatar` → 成员表 → GitHub 头像（`github.com/<用户名>.png`）→ 姓名首字生成的本地头像（首字 + 由姓名决定的稳定配色，离线可用）
- **跳转链接**：frontmatter 的 `link` → 成员表 → GitHub 个人页
- **悬停标签**：frontmatter 的 `contact` → 成员表 → GitHub 用户名 → 邮箱；全都没有时悬停不弹

其他规则：

- 不写 `author` 时页尾显示兜底的 `NKUwiki-Group`
- 非数组的写法（`author: Cure`、`author: { name: Cure }`）会被忽略；数组里缺 `name` 或名字为空的元素也会被忽略
- 名字本身带空格没问题，会整体当作一个名字；多个作者就写多个元素，页尾按声明顺序展示、不去重
- 名字或邮箱里含 `: `、`#` 或以 `@`、`?`、`&` 等开头时，用引号包起来，例如 `email: "mailto:a@b.com"`

### 其他开关字段

| 字段 | 作用 |
| --- | --- |
| `hideChangelog: true` | 隐藏页面的编辑历史区块 |
| `layout: wide` | 使用宽屏布局（适合大表格卡片页，如群汇总）；宽屏页面会自动隐藏字数与阅读时间，无需额外设置 |
| `article: false` | 让构建跳过这个 md——它不出现在侧栏、分类、标签、归档和搜索里（适合目录里的说明性文件） |

另有 VitePress 原生的 frontmatter（`layout: home`、`sidebar: false`、`outline`、`footer` 等，首页与地图页在用），普通文章不需要，完整列表见 [VitePress 官方文档](https://vitepress.dev/zh/reference/frontmatter-config)。

首页「活动」栏的数据文件（`docs/activity/`）用的是另一组专用字段（`title`、`date`、`end`、`campus`、`venue`、`link`、`description`），详见[该目录的说明](https://github.com/NKUwiki/NKUwiki/blob/main/docs/activity/README.md)。

## 图片与附件

- 图片放 `docs/public/img/目录编号/文章编号/`，如 `docs/public/img/04/08/主楼.png`。
- 正文引用写绝对路径：`![主楼](/img/04/08/主楼.png)`（不带 `public` 前缀）。
- 校园地图点位的图片单独放 `docs/public/map/pic/`，引用路径为 `/map/pic/...`。
- 建议图片宽度不超过 1200px、优先 webp/png，控制体积。

## 正文写作规范

- 一级标题由 `title` 生成，正文从 `##` 二级标题开始。
- 语法基础与扩展语法（表格、脚注、公式、代码块等）见[Markdown 语法教程](/pages/markdown-syntax/)。
- 排版细节遵循全站约定：中文与英文/数字之间加空格、使用全角标点，详见[网页写作排版规范](/pages/writing-guidelines/)。
- 站内链接用 permalink（如 `/pages/Contributing/`）；链接校园地图写 `/map`（不带尾部斜杠，否则构建会报死链）。

## 可调用的站点功能

写正文时可以直接使用这些站内能力：

| 功能 | 用法 |
| --- | --- |
| 卡片列表 | 用 `::: cardlist` 包裹一个 Markdown 表格，自动渲染成卡片网格，详见[卡片列表](#卡片列表-cardlist) |
| 数学公式 | `$行内公式$` 与 `$$公式块$$`，由 MathJax 渲染 |
| 脑图 | 使用 markmap 代码块绘制思维导图 |
| 地图点位关联 | 校园地图的标点可以链接到你的文章并直达某一章，见[校园地图数据维护](#校园地图数据维护) |

## 卡片列表（cardlist）

用 `::: cardlist` 容器包裹一个 Markdown 表格，站点会把它渲染成卡片网格——数据仍然写在表格里，方便编辑：

```md
::: cardlist
|    名称    |         加入方式          |             二维码                                        |
| :--------: | :-----------------------: | :-------------------------------------------------------: |
| NKUwiki组 | :qq:[1108024910](链接) | <QrCode src="https://qm.qq.com/q/xxxx" label="NKUwiki项目组" :size="128" /> |
|  某社团    | :wechat: 公众号私信加群   |                                                            |
:::
```

### 表头（列名）决定渲染方式

| 列名 | 行为 |
| --- | --- |
| 第一列 | 卡片标题 |
| `头像` | 卡片头像，写 `![](/img/…/xx.jpg)`、链接或裸路径均可；没有此列时群组卡片显示按 QQ 号生成的首字头像 |
| `加入方式` / `群号` | 渲染为联系区，支持[图标短码](#图标短码)与链接；群组模式还会自动从单元格提取 QQ 号 |
| `二维码` | 配合 `<QrCode src="链接" label="名称" :size="128" />` 组件，悬停显示大图 |
| `备注` | 渲染为卡片上的徽章 |
| `文章` / `详情` | 填一个链接（如 `[查看详情](/pages/Xxx/)`），整张卡片可点击跳转；该列本身不显示在卡片上 |
| `菜品` | 美食卡评分，写四段数字如 `4-3-4-4`，自动标注菜品/菜量/环境/总体 |
| `评价` / `主要工作` | 渲染为描述段落 |
| 其他列名 | 渲染为通用的「列名： 内容」字段，空单元格自动跳过 |

表头里出现「群号 / 加入方式 / 二维码」时整表按**群组卡片**渲染（带头像与联系区），否则按**美食卡片**渲染（带菜品评分），无需手动指定。

### 图标短码

单元格中写 `:名称:` 会替换为对应图标，当前支持 `:qq:`、`:wechat:`、`:feishu:`、`:mail:`、`:link:`；需要更多图标时在 `lib/content/cardlist.ts` 的 `cardIcons` 中追加（需 import 对应的 `@iconify-icons/ri/*` 图标）。

## 校园地图数据维护

[校园地图](/map)的点位、分类与校区配置都在 `docs/.vitepress/theme/components/map-data.js` 一个文件里。该文件自上游地图项目转换生成，**不参与 ESLint**（保持上游书写风格），修改后跑 `pnpm dev` 打开 `/map` 即可看效果。

### 新增或修改点位（BUILDINGS）

地图上的每个标点对应 `BUILDINGS` 数组里的一条数据：

```js
{
  "id": "n_landmark_01",                  // 唯一标识，不要与其他点位重复
  "name": "南开大学主楼",                  // 标点与列表里显示的名称
  "category": "landmark",                 // 分类 key，必须是 CATEGORY_CONFIG 里已有的
  "campusId": "n",                        // 所属校区："n" 八里台 / "j" 津南
  "coord": [117.171274, 39.102101],       // 坐标 [经度, 纬度]
  "desc": "八里台校区标志性主楼……",        // 详情卡上的介绍文字
  "photos": ["/map/pic/xxx.png"],         // 详情卡图片，可选，文件放 docs/public/map/pic/
  "article": "/pages/BalitaiCampus/#主楼"  // 关联文章，可选，见「点位关联文章」
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一标识。惯例是「校区前缀 + 分类 + 序号」，如 `n_canteen_02`、`j_library_01` |
| `name` | 标点气泡、左侧列表与详情卡显示的名称 |
| `category` | 决定标点图标与颜色，可用取值见[可用的 category](#可用的-category) |
| `campusId` | `"n"` 八里台校区、`"j"` 津南校区 |
| `coord` | `[经度, 纬度]`。用[高德坐标拾取器](https://lbs.amap.com/tools/picker)搜索或点选获取（GCJ02 坐标，不要用 GPS 原始坐标或百度坐标，会有偏移）。导航外链与步行路线都会自动换算 |
| `desc` | 点击标点后详情卡里的介绍，一两句话即可 |
| `photos` | 详情卡图片数组，可选。图片放进 `docs/public/map/pic/`，路径以 `/map/pic/` 开头 |
| `article` | 关联文章，可选，用法见[点位关联文章](#点位关联文章) |

#### 可用的 category

点位的 `category` 必须是 `CATEGORY_CONFIG` 里已有的 key，当前共 17 个：

| key | 显示名 | 典型用途 |
| --- | --- | --- |
| `landmark` | 地标建筑 | 主楼、马蹄湖、纪念雕塑等标志性地点 |
| `teaching` | 教学楼 | 公共教学楼、电教中心 |
| `college` | 学院楼 | 各学院的教学科研楼（伯苓楼、省身楼等） |
| `admin` | 行政楼 | 机关办公楼、出版社 |
| `library` | 图书馆 | 各校区图书馆 |
| `dormitory` | 学生宿舍 | 学生公寓区 |
| `canteen` | 食堂 | 各食堂 |
| `sports` | 运动场馆 | 田径场、体育馆、游泳馆 |
| `theater` | 剧场 | 音乐厅、演出与活动场地 |
| `hospital` | 校医院 | 校区医院 |
| `gate` | 校门 | 各校门 |
| `busstation` | 校车站 | 校内巴士站点 |
| `transit` | 轨道交通 | 地铁站 |
| `express` | 快递点 | 快递驿站 |
| `shop` | 商铺 | 校内超市、门市 |
| `food` | 附近美食 | 校外餐馆（如西南村） |
| `tool` | 维修点 | 打印、维修等服务点 |

都不合适时，需要在 `map-data.js` 里新增分类——文件头注释写明了要同步修改的三处配置；不熟悉的话也可以请管理员代为添加。

### 点位关联文章

详情卡可以带一个**「查看相关文章」**按钮，点击跳转到站内对应文章；链接带锚点时会**直接定位到文章里的那一章**（例如从主楼点位直达《八里台校区建筑》的「主楼」一节）。

在点位数据里加 `article` 字段即可：

```js
"article": "/pages/BalitaiCampus/#主楼"
```

- 链接写文章的 `permalink`；`#` 后面填文章里的某个 `##` 章节标题（与标题文字一致），点击按钮就会直接滚到该章节；不写 `#` 则打开文章开头
- 没写 `article` 字段的点位不显示按钮
- 写「校园建筑」类文章时，建议章节标题与地图点位名称对应，方便这样关联

## 本地预览

改完后建议本地跑一下确认效果（需要 Node.js 22.19+/24.11+/26+ 与 pnpm 11.24.0）：

```bash
pnpm install
pnpm dev      # http://localhost:5173/ 打开自己改的页面检查
```
