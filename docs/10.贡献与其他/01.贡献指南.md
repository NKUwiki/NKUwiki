本篇先讲投稿的**授权约定**，再介绍**写作层面的规范**：文章放在哪里、怎么命名、Frontmatter 怎么写、图片放哪里。正文里能调用哪些站点能力（卡片列表、应用卡片、图片画廊、地图点位关联等）见姊妹篇[站点功能说明](/pages/SiteFeatures/)；通过什么渠道把文章交给我们，见[贡献方式](/pages/ContributionMethods/)。

## 投稿许可协议

> **提交投稿即视为同意本协议。** 凡以在 NKUwiki 发布或收录为目的，通过 GitHub Pull Request、Issue、电子邮件、QQ 群或其他方式提交原创文字、图片、表格、数据或其他站点素材，均视为你已阅读并同意按照 CC BY-NC-SA 4.0 协议授权，无需另行签署协议。

| 允许使用     | 任何人均可在非商业目的下复制、分享、修改和改编投稿内容。                                                                                                                                              |
| 必须署名     | 使用时必须注明原作者与来源「NKUwiki」（<https://freshnkuer.wiki>），附上协议链接；如果修改过，还必须说明作出了哪些修改。                                                                              |

转载、引用或改编时，建议至少标明以下信息：

```text

原作者：作者姓名
来源：https://freshnkuer.wiki/
协议：CC BY-NC-SA 4.0
修改说明：简要说明本次修改
```

**投稿不会转让你的著作权。** 你仍保留投稿内容的著作权；对于已经按本协议发布的版本，NKUwiki 和读者可以依据 CC BY-NC-SA 4.0 的条款继续使用，该授权不会因投稿被删除或后续撤回而失效。

提交内容时，你确认：

1. 内容由你独立创作，或者你已经取得原作者及相关权利人的充分授权；
2. 你可以合法地按 CC BY-NC-SA 4.0 授权该内容，且该授权不侵犯他人的著作权、肖像权、隐私权或其他合法权益；
3. 如果你使用了他人的文字、图片、图表等材料，已经明确标注来源并确认其许可允许当前用途；第三方材料不会仅因被提交给 NKUwiki 而自动改用本协议；
4. 合作创作的内容已经取得其他作者的同意。

如无法满足以上条件，请不要提交相关内容。完整条款见 [NKUwiki 内容许可协议](https://github.com/NKUwiki/NKUwiki/blob/main/LICENSE-CONTENT.md)（源码许可见 [LICENSE](https://github.com/NKUwiki/NKUwiki/blob/main/LICENSE)）及 [CC BY-NC-SA 4.0 法律条款](https://creativecommons.org/licenses/by-nc-sa/4.0/legalcode.zh-hans)。

## 文章放在哪里

正文都放在 `docs/` 下**带编号**的目录里，编号决定侧栏、分类页与标签页的顺序（见[排序规则](#排序规则)）。按内容类型对号入座：

| 内容类型                                  | 放到                                                            |
| ----------------------------------------- | --------------------------------------------------------------- |
| 入学手续、报到、军训、交通、反诈防骗      | `docs/01.新生入学/`                                             |
| 学分绩点、选课、考试、推免保研、竞赛证书  | `docs/02.浅谈学习/`                                             |
| 兴趣群、老乡群、学生组织、实验室汇总      | `docs/03.群汇总/`                                               |
| 单个社团/组织的详细介绍页                 | `docs/03.群汇总/05.组织详情/`                                   |
| 快递外卖、美食、周边、APP、校园建筑等日常 | `docs/04.校园生活/`（下设日常生活、学校系统、校园建筑等子分类） |
| Markdown、Git、编程、AI 等工具类内容      | `docs/05.计算机知识/`                                           |
| 本站协作说明、关于我们、友情链接          | `docs/10.贡献与其他/`                                           |
| 首页「活动」栏的活动信息                  | `docs/activity/`（不生成独立页面）                              |

几个约定：

- **不要新建顶层编号目录**。想加新大类，先在群里或 Issue 里提一句，多数内容能并入现有分类。
- 目录下可以再建**子目录**形成子分类（如 `04.校园生活/08.校园建筑/`），子目录里的文章在侧栏与分类页都会多一层，侧栏里子目录排在同级散文章之前。
- `categories/`、`tags/`、`archives/` 这些无编号目录是站点功能页，**不要往里面写文章**。
- 内容横跨多类时，放进主要服务的那一类，再用 `categories` / `tags` 补充。

## 命名规则

- 文件与目录都以「**编号.名称**」命名，如 `01.快递和外卖.md`；展示时自动去掉数字前缀，编号决定排序。
- 编号惯例：`00.` 放概览，`01.`–`09.` 放主题文章，`10.` 之后放 Q&A、附录等收尾内容，不必强行连续。
- 文件名会参与链接的自动生成，建议在 [Frontmatter](#frontmatter) 里手写 `permalink` 固定链接。
- 一篇文章一个 `.md` 文件；文件名里避免 `? # &` 等符号。

### 排序规则

文章与分类的先后顺序**只由文件名 / 目录名的编号决定**（`01.` 排在 `02.` 前），没有别的排序字段：

- 侧栏、分类页、标签页三处顺序一致：同级**先列子目录、再列散文章**，两者内部各自按编号排。
- 分类页里的子分类条目也按所在目录的编号排，并排在文章之前。
- 想调整顺序就改编号前缀，改完三处同时生效。
- **唯一例外**：[最近更新页](/archives/)按最后更新时间倒序排。
- 早期文章里可能残留 `order: 数字` 字段，该字段已废弃、不再生效，可以直接删掉。

## Frontmatter

Frontmatter 是文件顶部的元信息，被一对三短划线包裹。完整示例：

```yaml
---
title: 快递和外卖
description: 校内快递点与外卖取送指南。
date: 2026-09-01
lastUpdated: 2026-09-09
categories:
  - 校园生活
tags:
  - 校园生活
permalink: /pages/Delivery
---
```

| 字段          | 必填 | 说明                                                                                                                               |
| ------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `title`       | 是   | 文章标题，会覆盖正文里手写的一级标题，所以正文**不要再写一级标题**                                                                 |
| `description` | 建议 | 一句话简介，用于分享卡片与页面描述                                                                                                 |
| `date`        | 是   | 创建日期 `YYYY-MM-DD`，后续修改保留                                                                                                |
| `lastUpdated` | 条件 | 最近一次内容更新日期。新增、删改正文或修订信息时与内容同一提交更新；纯排版、分类调整不更新。未填写则以 `date` 作为最后更新时间显示 |
| `categories`  | 可选 | 补充分类。目录层级本身就是分类（如 `04.校园生活/08.校园建筑/` 自动是「校园生活/校园建筑」），一般不用再写                          |
| `tags`        | 可选 | 标签，出现在标签页与文章标题旁                                                                                                     |
| `permalink`   | 建议 | 固定访问链接，不写则由文件路径自动生成（带编号、会随改名变化），强烈建议手写                                                       |
| `author`      | 可选 | 页尾「本文作者」。不写则显示兜底的 `NKUwiki-Group`                                                                                 |

### author 的写法

支持两种写法，可以在同一个数组里混用：

```yaml
# 写法一：只写名字字符串，其余信息（GitHub、头像、联系方式）按名字到
# docs/.vitepress/data/members.ts 的成员表里查
author: [Cure, NKUwiki-Group]

# 写法二：对象形式，适合不在成员表里的客串作者就地补字段；
# 显式写了的字段会覆盖成员表里的同名信息
author:
  - name: 客串作者        # 必填，缺 name 的整条忽略
    github: someones      # GitHub 用户名：自动取头像与个人页链接
    avatar: https://img.example.com/avatar.png   # 自定义头像，优先级最高
    link: https://blog.example.com               # 点击头像跳转的链接
    contact: QQ：123456789                       # 悬停头像时显示的联系方式
    email: guest@example.com                     # 邮箱（写裸邮箱会自动补 mailto:）
```

各信息的取值优先级（从前到后）：

- **头像**：frontmatter 的 `avatar` → 成员表 → GitHub 头像（`github.com/<用户名>.png`）→ 姓名首字生成的本地头像（首字 + 由姓名决定的稳定配色，离线可用）
- **跳转链接**：frontmatter 的 `link` → 成员表 → GitHub 个人页
- **悬停标签**：frontmatter 的 `contact` → 成员表 → GitHub 用户名 → 邮箱；全都没有时悬停不弹

其他规则：

- 不写 `author` 时页尾显示兜底的 `NKUwiki-Group`
- 非数组的写法（`author: Cure`、`author: { name: Cure }`）会被忽略；数组里缺 `name` 或名字为空的元素也会被忽略
- 名字本身带空格没问题，会整体当作一个名字；多个作者就写多个元素，页尾按声明顺序展示、不去重
- 名字或邮箱里含 `: `、`#` 或以 `@`、`?`、`&` 等开头时，用引号包起来，例如 `email: "mailto:a@b.com"`

### 其他开关字段

| 字段                  | 作用                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------ |
| `hideChangelog: true` | 隐藏页面的编辑历史区块                                                                     |
| `layout: wide`        | 使用宽屏布局（适合大表格卡片页，如群汇总）；宽屏页面会自动隐藏字数与阅读时间，无需额外设置 |
| `article: false`      | 让构建跳过这个 md——它不出现在侧栏、分类、标签、归档和搜索里（适合目录里的说明性文件）      |

另有 VitePress 原生的 frontmatter（`layout: home`、`sidebar: false`、`outline`、`footer` 等，首页与地图页在用），普通文章不需要，完整列表见 [VitePress 官方文档](https://vitepress.dev/zh/reference/frontmatter-config)。

首页「活动」栏的数据文件（`docs/activity/`）用的是另一组专用字段（`title`、`date`、`end`、`campus`、`venue`、`link`、`description`），详见[该目录的说明](https://github.com/NKUwiki/NKUwiki/blob/main/docs/activity/README.md)。

## 图片与附件

配图**优先传到图床**，不必放进仓库——仓库只留站点自身资源与已有旧图。

1. 打开 <https://upload.freshnkuer.wiki>，用 GitHub 或 Cloudflare 账号登录。
2. 选好栏目与文章再上传；美食封面手填目录 `food/shots`，地图照片手填 `map/pic`（系统会补成 `img/food/shots`、`img/map/pic`）。**新文章还没合并到 `main` 时目录树里没有它**，手填 `栏目编号/文章编号` 即可。
3. 复制返回的地址，正文照常写站内路径：`![飞书](/img/04/09/飞书.png)`。非组织成员的上传要等管理员批准，**批准前别把链接写进 PR**——若与已有文件重名，实际落盘名可能被自动加哈希后缀。

上传的图归档在桶里的 `img/<栏目>/<文章>/`，仓库一个文件都不增。构建期由 `replace-assets` 插件把产物里的 `/img/...` 统一改写到图床（开关是 `.github/workflows/static.yml` 的 `WIKI_ASSETS_BASE`），所以**正文永远只写站内路径**，不要直接把图床完整地址抄进文章——将来换存储只改一处，文章一个字都不用动。

下面这些**必须**留在仓库 `docs/public/`，删了站点就会缺东西：

- `favicon-*.svg`：HTML 里的 `<link>` 会被改写到图床，但 `manifest.webmanifest` 里仍是 `/favicon-*.svg`，站点必须自己有一份；
- `og-default.png`：`og:image` 用的是站点绝对地址（`https://freshnkuer.wiki/…`），不走改写；
- `manifest.webmanifest`、`robots.txt`、`CNAME`：public 是原样拷贝，插件碰不到；
- `img/logo.svg`：友情链接等处按站点域名直接引用；
- 已经存在于 `docs/public/img/` 里的旧图（不必重复上传，正文照旧引用）。

放仓库时的约定：

- 图片放 `docs/public/img/<栏目编号>/<文章编号>/`，如 `docs/public/img/04/09/飞书.png`（对应 `docs/04.校园生活/09.学校系统/02.常用APP.md`）。
- 正文引用写绝对路径，目录同上：`![飞书](/img/04/09/<文件名>)`（文件名含扩展名，不带 `public` 前缀）。
- 地图点位图放 `docs/public/img/map/pic/`，引用 `/img/map/pic/...`；美食页视频封面放 `docs/public/img/food/shots/`。**文章配图一律落在 `img/` 下**——图床上传器只管理这个子树，放到别处的新图走不了上传流程。
- 建议图片宽度不超过 1200px、优先 webp/png，控制体积。

只在图床、还没入库的图，本地 `pnpm dev` 里会显示不出来（本地确实没有这个文件）；要连图床一起预览，用 `WIKI_ASSETS_BASE=https://img.freshnkuer.wiki pnpm build` 构建后再 `pnpm preview`。

## 正文写作规范

- 一级标题由 `title` 生成，正文从 `##` 二级标题开始。
- 标准语法（标题、强调、列表、引用、代码、链接、图片等）见[Markdown 基础语法](/pages/markdown-basic/)；扩展语法（表格、脚注、公式、任务列表等）见[Markdown 常见扩展语法](/pages/markdown-extended/)。一页速查见[语法速查表](/pages/MarkdownCheatsheet/)，本站专属写法见[本站特有的 Markdown 语法](/pages/MarkdownGuide/)。
- 排版细节遵循全站约定：中文与英文/数字之间加空格、使用全角标点，详见[网页写作排版规范](/pages/writing-guidelines/)。
- 站内链接用 permalink（如 `/pages/Contributing/`）；链接校园地图写 `/map`（不带尾部斜杠，否则构建会报死链）。
- 卡片列表、应用卡片、图片画廊、地图点位关联等站点功能的用法，见[站点功能说明](/pages/SiteFeatures/)。

## 本地预览

改完后建议本地跑一下确认效果（需要 Node.js 22.19+/24.11+/26+ 与 pnpm 12.15.0）：

```bash
pnpm install
pnpm dev      # http://localhost:5173/ 打开自己改的页面检查
```
